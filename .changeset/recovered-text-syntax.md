Keep the text a parser could not place in the normalized string. In a file with a syntax error, tree-sitter parks what it skips in an ERROR node marked as an extra, and every extra was left out with the comments, so an edit there (`export type T = | A B` → `| X B`, `save(a b)` → `save(a c)`, `f(): Map<A B, C>` → `Map<A X, C>`, `class K extends A B` → `extends A X`) moved no fingerprint. Comments are now the only extras left out, and an ERROR is read in a function's or a class's head too, where the api axis leaves it out. A comment, a stray `)` and the spacing inside a run of characters the parser could not lex still change nothing. A Symbol whose source holds such a part gets a new `syntax` fingerprint, so an `aburi diff` against an IR an earlier version wrote reports it as syntax-changed once. That includes code `tsc` accepts and the grammar has no rule for: a bare `&` in JSX text or in an attribute's string (`href="/x?a=1&b=2"`), an escape only a tagged template may hold (``String.raw`C:\Users\u` ``), and a variance modifier on a class's or a type alias's type parameters (`class E<in out T>`), though not on an interface's, which is described by its body.
