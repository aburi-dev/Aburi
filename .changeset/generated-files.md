Mark the Symbols of a generated file with `inGeneratedFile: true`, and count their calls apart. A file is generated when one of the comments it opens with says so: the `@generated` tag, `this file` or `this code` said to be (auto-)generated, or a header's `Generated by …` beside `do not edit`. Such a file is scanned as before, its calls resolved and its effects propagated, but `stats.callResolution.generated` holds the census of its calls, and the census line `aburi scan` and `aburi diff` print counts the authored code and ends with the generated files' calls. `@aburi/types` exports the census's type as `CallCensus` and the authored census as `authoredCallCensus(stats)`.

`aburi diff` reports the changes of generated files on one line, in a last `⚙ Generated files` section, instead of in the sections above it: each file with its changes counted by status, an `unknown` change with the skip that made it, and the count of their edges. The Summary line counts them as `· N in generated files`. A generated test file goes there too, so it leaves `🧪 Test files` and `· N in test files`. `--fail-on` still counts every change of a generated file.

The integrity check now refuses a document in which the Symbols of one file disagree on `inTestFile` or on `inGeneratedFile`.
