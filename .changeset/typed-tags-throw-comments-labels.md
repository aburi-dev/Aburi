Read constructs the plugin read wrongly.

- A tagged template with type arguments is a call of its tag, wherever it is written and however the grammar spreads it: as an instantiation it completes with a `!`, as comparisons, a union, a sequence or a shift (``sql<number>`…` ``, ``sql<number | null>`…` ``, ``f<A, B>`…` ``, ``q<Array<Row>>`…` ``), or as a concise arrow called with the template (``(p) => p.$queryRaw<Row[]>`…` ``). ``prisma.$queryRaw<User[]>`…` `` was a call to `<computed>`, so `effects-prisma` never declined it as a raw query; it is now `prisma.$queryRaw`, as the untyped tag is, and a workspace function used as a tag resolves. Every path that reads a declaration reads it as it reads the untyped tag: an exported `const`, `export default` and an object entry holding one record its call, `returns` and `receiverCall` name it, and a concise arrow that ends in one is a `function`, not a `const`. An operator applied to the tag (``1 + sql<number>`…` ``, `!sql<…>`, `typeof sql<…>`) no longer hides the call. In a JavaScript file, which has no type arguments, ``a < b > `…` `` stays two comparisons and records no call, and the `!` the grammar completes such a tag with now reports, as `tsc` reports the type arguments there. An escape only a tag allows (`\u`, `\x`) in such a tag's template no longer reports in a TypeScript file.
- An instantiation expression in a callee is read through as a type assertion is: `(f<string>)()` calls `f` rather than `<computed>`, `new (Foo<string>)()` constructs `Foo`, and `a.b<T>!()` is `a.b!`.
- Fingerprints move once for these. A `return` or a concise body that is such a tag loses its `return` rule, and an exported `const` or an object entry holding one loses its `value` rule, as a call has neither, so `logic` moves. A rule that applies an operator to the tag keeps it, now spelled with the type arguments TypeScript reads (``1 + sql<number> `x` ``), so `logic` moves there too. A concise arrow that ends in one changes kind from `const` to `function`, and its `syntax` now reaches the template. A chain on the tag's result records its outer call first, as `f().g()` does. The new calls move `logic` only where an effects plugin classifies them.
- A comment right after `throw` is no longer read as the thrown value, so `throw /* legacy */ new NotFound()` keeps `NotFound` in `signature.throws` and in its `throw` rule. The same holds for a comment after a top-level `await`.
- A label's name is part of the normalized string, so swapping `break outer` and `break inner` moves `syntax`. Every Symbol whose body holds a label gets a new `syntax` fingerprint once.
