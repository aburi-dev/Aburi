Effects and calls that share a line now keep the order the language plugin wrote them in, which is source order, as the IR schema states. Before, they were sorted by target. Swapping two effects written one after another on one line (`await a.save(); await b.log()` becoming `await b.log(); await a.save()`) now moves the `logic` fingerprint, and renaming one of the targets no longer reorders them. Source order is not run order for nested calls: `@aburi/lang-typescript` writes a call before the calls inside it, so `publish(await write())` lists `publish`, then `write`.

A Symbol with two or more locally detected effects on one line, whose targets were not already in that order, gets a new `logic` fingerprint once. An IR scanned before this release, compared with one scanned after, reports those Symbols as logic changes and trips `--fail-on logic-changed` or `changed`, and there is no `grammarRevision` counterpart for `logic` to warn you that a stored IR predates this release. No `api` or `syntax` fingerprint moves. The Markdown projection keeps the IR's order within a line, so it lists a Symbol's same-line effects and calls in the new order too. On this repository, scanning one tree with both versions moves no fingerprint, with the TypeScript plugin alone and with each showcase example's effect plugins, and a diff of the two IRs reports nothing; with the TypeScript plugin alone, 1,081 of its 4,787 Symbols list their same-line calls in a new order in `calls[]`. Rescan the base rather than comparing against a stored IR. `aburi diff <base>..<head>` scans both sides with the installed plugins and is unaffected.
