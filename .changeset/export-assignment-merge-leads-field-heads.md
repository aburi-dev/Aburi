Give the value `export =` makes a module a Symbol. `export = function handler() {}` and `export = class UserService {}` are named by their own names, with the class's members, unless the module binds that name to something else; an anonymous one, or one whose name is taken, is `<default>`; a call handed a function is the `<default>` const `export default` gives it; any other value, such as `export = { find() {} }` or `export = Routes.handler`, is a `<default>` const holding the calls of the functions it holds; and `export = handler` makes `handler` public. Each carries the new `derivedBy` entry `export-assignment`, which `@aburi/types` exports as `EXPORT_ASSIGNMENT_DERIVED_BY` and which names the module's export `export=` for the api fingerprint, so the statement becoming `export default` is an api change. `export = h` of an import gives no Symbol: the import's edge re-exports it as `export=` (`@aburi/core` exports the name as `EXPORT_ASSIGNMENT_NAME`). Before, the statement extracted nothing, so the module's only export was in no Symbol and an edit to it reported nothing.

A call reaches the value through `import h = require("./m")`, `const h = require("./m")`, `import * as h from "./m"` (as TypeScript types it without `esModuleInterop`), a member of any of them (`h.of()`), and a default import, and through a module that re-exports it with `import h = require("./m"); export = h`. A module that writes `export =` is never read by name, so a member the value does not hold is `no-match` rather than a function of that name the module declares beside it, whether the value is dropped, an object literal or a module the scan could not read. An effect plugin is no longer asked about a method of a class behind `export =`, as it is not about one behind `export default`. `export default h as T` of an import now re-exports `h`, as `export default h` does.

What a module exports is now read with its dropped declarations, as an export clause's already was, so two `export *` targets that both export a name disagree on it even where a drop rule removed one of them, and a call through the barrel is `ambiguous` instead of reaching the other.

When an interface or a type alias is written above a function, a binding, an enum or a namespace of its name, that declaration now leads the merged Symbol, as a class already did, and an enum leads a namespace written above it: what exists at run time leads what only adds to it or describes it. `export type User = ReturnType<typeof User>` above `export const User = make(…)` is a `const` that keeps its calls instead of a type alias dropped with them, and `User()` resolves to it. A namespace, though it may hold only types, leads an interface it merges with wherever either is written. `kind` is read by the api fingerprint, so against an IR an earlier version wrote, each Symbol whose lead changes kind reports one api change.

A field holding a function now carries its type annotation and its `=` in its normalized string, so editing the annotation, or rewriting the field as a method of its name, moves the member's `syntax` and not only its class's. Against an IR an earlier version wrote, every field holding a function reports a syntax-only change once.

`export default abstract class { … }` and a `static` index signature in a class body parse clean, with whitespace or comments between the tokens: the grammar refuses both modifiers, so the file is reparsed with them blanked, and the normalized string keeps them. `abstract` with `class` on the next line still reports, as `tsc` reads no modifier there, and so does a `static` index signature outside a class body. Before, the default export lost every Symbol of its file, and the index signature left a parse error in its class.
