Write a rule's strings, a type and a decorator in one canonical spelling, so running a formatter moves no fingerprint. The text is rebuilt from the syntax tree's tokens instead of copied from the source: comments and line breaks are left out and the spacing between tokens is regenerated, a string is written as its value between `"` (`'it\'s'` and `"it's"` both read `"it's"`), a quoted key that needs no quotes is written bare, a `,` before a closing bracket and the `;` that ends a statement are left out wherever the statement is written, a block's statements and a class's members are joined by `; `, an arrow's lone parameter is written in parentheses, `new A` is written `new A()`, a number's letter case and zeros are settled (`1.50` reads `1.5`), and parentheses are written where readers mix operators up (`a && b || c` reads `(a && b) || c`) and left out where the grouping does not need them: around an operand precedence already groups, the head of an access or a call, anything but a sequence in a slot that takes any expression, and a type that binds tighter than any operator, including those a formatter wraps around JSX laid out over lines. JSX reads as React renders it: no space is added between children, a run of text is read whole with its character references, the line breaks and indentation around it are dropped, and the `{" "}` a formatter writes where it breaks a line reads as the space it is. So `'admin'` → `"admin"` in a guard no longer moves `logic`, a string literal type's quotes no longer move `api`, and `@Controller('users')` → `@Controller("users")` no longer lists the class and every method under API changes. Spellings of different code stay apart: `- -a` and `--a`, `(a + b) * c` and `a + b * c`, `(a?.b).c` and `a?.b.c`, and the text between JSX tags is content. Whitespace inside a literal is the exception: the core collapses every run of it in a rule string, so `"a  b"` and `"a b"` give one string.

The syntax axis reads the same way: a string's quotes and escapes, parentheses the grouping does not need, `new A` against `new A()`, a quoted key's quotes, a number's spelling and the layout of JSX text no longer move `syntax`, and the character a JSX character reference names (`&amp;` against `&lt;`) now does.

`Decorator.raw` and `Decorator.arguments` now hold the canonical spelling rather than the source text, so the report writes `@Post("/invoices")` for `@Post('/invoices')`.

The fingerprints move once for Symbols whose source was not already written this way, with no change to the source: on the pinned `cal-com` checkout, `api` for 204 of the 14,531 kept Symbols, `logic` for 2,334 and `syntax` for 2,157. An `aburi diff` against an IR an earlier version wrote reports them as changed; one that scans both sides with this version does not.
